# Local debugging threat model

CDP exposes the full capabilities of a logged-in desktop application to other local processes. They may read private state or control the app independently of this tool. Restricting our code to cosmetic DOM/CSS operations does not turn CDP into a read-only interface. Only enable debugging on a trusted machine for an explicit session, and fully quit the app yourself afterward to close its listener.

The CLI builds `http://127.0.0.1:PORT/json/list` internally. It uses a 3-second deadline, a 1 MiB response limit and `redirect: 'error'`; redirected URLs and malformed target shapes are refused. Page targets must have exact `https://www.tradingview.com/chart/` or `https://tradingview.com/chart/` routes, optionally with a chart identifier/query/fragment. Credentials, explicit authority ports, suffix hosts, encoded/ambiguous paths and unrelated targets are rejected.

Before opening a socket, its complete URL must equal `ws://127.0.0.1:PORT/devtools/page/ID` with the same validated port and target ID. Remote hosts, hostname aliases, userinfo, queries, fragments and browser sockets are rejected. There are no other runtime network endpoints. Node environment-proxy activation is refused before any HTTP/socket call. Use a direct local Node networking environment; do not force global proxy dispatchers onto loopback traffic.

The CDP client has connection/call deadlines, bounded messages and cleanup on close, error, malformed input and failed sends. It permits only frame discovery, isolated-world creation and evaluation of the hardcoded DOM program. The main frame URL is checked before creating a named isolated world, and `location.href` is checked again inside the injection before any DOM work. A bounded retry handles execution-context navigation races. Evaluation uses the isolated context ID and JSON serialization of trusted generated CSS. Skin files are never evaluated.

Only one owned style ID and one owned root attribute are changed. Bounded, validated inert restoration metadata is kept on that owned style and root attribute, not only in an isolated-world global: reconnecting may destroy the global while the shared DOM survives. This preserves the original attribute's presence/value across reconnects, theme replacements and loss/recreation of the owned style. Repeated applies update the same style; removal only removes the recognized owned node and restores the attribute when its current value is still ours. Foreign style-ID collisions are refused and later foreign attribute changes are preserved. Reload discards injected DOM/world state; watch reacquires the current chart and reapplies. A watch session tries to remove its touched charts on Ctrl+C/SIGTERM; if it cannot reconnect, it truthfully reports cleanup failure. App reload/exit also clears injections. Concurrent skinning sessions are not coordinated; use one session per app.

The launcher uses a shell-free executable/argument array and no profile override. Windows package discovery reads only package name/install location through a fixed, bounded, hidden PowerShell command; macOS bundle executable discovery uses fixed PlistBuddy arguments. It never patches binaries/ASARs, reads credentials/cookies/localStorage/chart/account contents, accesses TradingView application APIs, changes market/order values, opens firewall rules, binds publicly or disables security flags. It never terminates the user's app. No wildcard remote-origin flag is used.

Doctor output contains only eligible page counts and local port readiness. Injection output is limited to operation status and bounded selector/geometry/computed-background counts; it contains no DOM text, screenshots, URLs, IDs or account contents. No analytics, telemetry, permanent agent, scheduled job, autostart or copied app assets are included.

Private observations, screenshots, recordings, paths, debugging IDs and receipts must stay outside versioned files. Synthetic test fixtures only. Report security issues privately using this repository's **Security → Report a vulnerability** feature. Do not post private application state, credentials, debugging IDs or screenshots in a public issue.
